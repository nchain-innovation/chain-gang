# Current Chronicle CODESEPARATOR and execution termination

BSV Node v1.2.3 scans scriptCode when constructing an OTDA preimage. On a truncated push it writes the prefix through the failing GetOp cursor. The CompactSize still declares the original script length minus separator opcodes reached by the scan. BIP143 writes all of the selected scriptCode bytes. An executed top-level OP_RETURN can leave a truncated push in scriptCode without ever executing or parsing that push during verification. See [the node's OTDA serializer](https://github.com/bitcoin-sv/bitcoin-sv/blob/v1.2.3/src/script/interpreter.cpp#L1862-L1891) and [GetOp2](https://github.com/bitcoin-sv/bitcoin-sv/blob/v1.2.3/src/script/script.h#L165-L199).

A branch-local OP_RETURN suppresses further execution while the interpreter continues to decode instructions. A truncated push encountered during that scan fails with BAD_OPCODE even when the signature verified. The library now diagnoses truncated pushes in skipped instructions and applies the correct OTDA byte boundaries. See [the node's execution loop and OP_RETURN](https://github.com/bitcoin-sv/bitcoin-sv/blob/v1.2.3/src/script/interpreter.cpp#L436-L459) and [termination rules](https://github.com/bitcoin-sv/bitcoin-sv/blob/v1.2.3/src/script/interpreter.cpp#L856-L871). See also #255.

`scripts/node-chain/chronicle_separator_exit.py` uses independent preimage construction, newly confirmed post-Chronicle outputs and real admission and block validation. Run on a fresh default-profile node using the Apple Container launcher in [node-chain-validation.md](node-chain-validation.md). The matrix covers four truncation shapes, both digest types, executed and skipped separators, branch-local termination, and mixed-flag multisig in both script phases. The two valid signatures must match to reach a malformed third pair. Altering either signed scriptCode makes matching terminate earlier. The Rust test replays the 44 matrix transactions and three pre-fix discrepancy receipts.
